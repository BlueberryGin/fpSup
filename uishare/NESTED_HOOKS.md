# 套娃 hook（nested hooks）—— 不複製原廠資源的添加規則

2026-10-04 定案，取代「複製整個資源、改指標」的做法（字串池先做；頁面見 §6）。
適用：SIGMA fp Ver.5.02，所有會往原生 UI 添加東西的 sup。

## 0. 為什麼

uishare 第一版要加任何東西都先複製整份資源再改指標：OG3K 為了一個 5 B 的字串 `"OG3K"`
複製了整個字串池（176,152 B，配置 ~192 KB），再為了改兩個字複製整頁 B2_5（118,123 B）；
raw-view 為了改計數複製 ColorButtonMenu（33,503 B）。複本不釋放，sup 越多、改同一頁越多次，
就越疊越多。添加的東西越小，浪費越大 —— 方向本身不對。

## 1. 形狀

```
韌體呼叫 F(r0, r1, …)            ← 照舊，參數、回傳值、呼叫點都不變
  F 的第一個字 = B.W → cave veneer → 最外層 C
      C：是我的？ → 回答，bx lr 回到韌體
         不是     → r0..r3 原封不動，尾呼叫 C.next
        └ B：同上，next → A
            └ A：同上，next → 原廠行為（A 自帶的重寫）
```

- **韌體不知道有幾層**，也不需要知道。每一層的簽名就是原廠函式的簽名。
- **「下一層在哪」是每層自己記的**（存在自己的標頭），不是參數。
- 命中就 `bx lr`；沒命中是尾呼叫（不壓堆疊、不存 LR），疊幾層堆疊都不加深。

## 2. 規則

1. **只回答自己的，其餘原樣往內傳。** 不改 r0–r3、不改它們指到的東西；一層不能「修飾」別層的答案。
   需要修改輸入再交下去的點（例如記錄解析器）不適用本規則，見 §6。
2. **只套在 leaf 函式上，最內層自己重寫原廠行為。** 掛鉤點第一個字已被 B.W 蓋掉，
   跳回原廠會再進最外層 → 無限迴圈。所以只選短、無副作用、行為能完全重寫的 leaf；
   重寫要在 unicorn 對真映像證明與原廠逐值相同。
3. **安裝時認娃娃，不認就放棄。** 掛鉤點上是原廠字 → 內層 = 自帶的原廠重寫；
   是 B.W → veneer（`ldr.w pc,[pc]` + 位址）→ 入口前的標頭版本對、**名字是登記簿上持有這個點的 sup**（§4）→ 內層 = 它；
   其他任何東西 → 這個 sup 的這項添加不裝（`UIA_HOOK`），別人的東西不動（uishare 守則 4）。
   同一組的幾個掛鉤點必須指向同一層，否則也放棄。
4. **編號開機時發，不寫死。** 每層的範圍 = 內層的終點起；最內層從約定的起點開始。
   載入順序不同只會讓編號不同，不會讓結果不同（uishare 守則 1）。
   例外：id 已寫死在沒有原始碼的程式裡的（Jose 的 Formats `FFFFFFD0..F6`）用 `uis_layer_fixed`，
   範圍必須在 `0xF0000000` 以上、不和串上任何層重疊；之後發號會跳過它（發號只看 `0xF0000000` 以下的層）。
5. **先備好，最後才接上。** 常駐區配置、複製、寫標頭 → D-cache clean → I-cache invalidate
   → 才改掛鉤點；多個掛鉤點時，先接「會被韌體拿來檢查」的，最後接「會產生新值」的。
   掛鉤點都是 4 對齊，B.W 是一次 32 位元寫入。
6. **常駐。** 層的程式與資料放自己向配置器要的記憶體，不放 staging（loader 返回就釋放）；
   veneer 放 cave（`CAVE_BUMP` `0xC072E060` 配置器，stage2 每次開機重設）。
7. **掛鉤點以原廠字宣告成 4-byte 段落。** stage2 journal、關機寫回，整串娃娃一起卸下
   （`HOOKS_AT_POWER_OFF.md`）。多個 sup 宣告同一點、同一個原廠字是允許的（同 `C05E5BEC`）。
8. **不拆、不卸、不重排。** 開機裝上就留到關機；中間一層不能拿掉。

## 3. 字串：三個掛鉤點（韌體 Ver.5.02，2026-10-04 反組譯）

| 點 | 原廠字 | 原廠行為（最內層照寫） | 誰呼叫 |
|---|---|---|---|
| `C05E5B58` 解析 | `3FFFF1B1` | `r1 == FFFFFFFF` 或 `r1 >= [r0+0x10]` → 0；否則 `[r0+0x14] + r1` | 記錄解析器 `C05E6400`（約 50 處）、`C05E7B40`、`C05E8070` |
| `C05E61C8` 擁有 | 讀映像 | `[r0+0x14] <= r1 < [r0+0x14]+[r0+0x10]` → 1，否則 0 | 只有配置器的 free（`C05E8E0E`）、realloc（`C05E8E78`） |
| `C05E61E0` 剩餘 | 讀映像 | `[r0+0x10] + [r0+0x14] - r1` | 只有 realloc（`C05E8E90`），決定 memcpy 長度 |

**為什麼不能只掛解析器**：解析出來的字串指標會被物件保存，之後被 free / realloc。
配置器用「擁有」判斷「指標在池裡 → 借來的，不 free」，不在池裡就交給原廠 free。
只掛解析器、回傳池外指標 → 有一天會把我們的常駐記憶體交給原廠 free。
三點一起掛，私有字串就跟原廠字串一樣被當成「借來的」。

**第四個池檢查 `C05E9008`（不掛）**：它自己內聯「指標在 `[pool, pool+len)`」，不經 `C05E61C8`。
呼叫者 `C05D9B40` 是「池內就借用，否則 `strlen+1` 配一塊、strcpy」；`C05CFC18`（3 處）算同一件事要的空間。
私有字串走「否則」：韌體複製一份自己擁有、自己釋放的小字串，不碰我們的記憶體 —— 安全，只多幾十 bytes。
所以不掛；若要讓私有字串連這份複本都省掉，再把它加成第四個點（同樣是 leaf，只改 r0/r2）。

每層：

- 解析：`base <= r1 < base+count` → 回傳第 `r1-base` 個字串；否則 next。
- 擁有：`data_lo <= r1 < data_hi` → 1；否則 next。
- 剩餘：`data_lo <= r1 < data_hi` → `data_hi - r1`；否則 next。

**起點 `0x40000000`**：遠大於任何池的長度（含 Lossless 的池副本），避開 `FFFFFFFF`（空）。
原廠池、`reader+0x10/+0x14`、池裡每個位移都不動 —— 直接讀池的程式（含 raw-view `stub_ai`）照樣對；
還在用池副本的 sup（舊 `ui_pool`）也相容，因為最內層讀的是 reader 當下的池。

## 4. 層的標頭（v5，2026-10-07：自描述）

層 = 一塊常駐記憶體，標頭在最前面，三個入口在標頭後的固定位移：

| 位移 | 內容 |
|---|---|
| +00 | 名字 8 B：裝這層的 sup 的檔名主檔名（`10LOSS`、`31FMT`），NUL 補齊 |
| +08 | 版本 5(自描述;之後只在欄位語意改變時升) |
| +0C | base（第一個私有位移） |
| +10 | count |
| +14 | data_lo（私有字串位元組起點） |
| +18 | data_hi（終點，不含） |
| +1C | next 解析（0 = 自帶原廠） |
| +20 | next 擁有 |
| +24 | next 剩餘 |
| +28 | 字串位址表 |
| +2C | QS 共用 id 的第一個(0 = 這層沒有;QS_SHARE.md §4.3) |
| +30 | QS enum:解析度值是它時,這層用自己的三個名字回答共用 id |
| +34 | QS 名字:三個字串位址的表 |
| +38 | 標頭長度(72;讀更後面的欄位前先看它) |
| +3C/+40/+44 | 解析/擁有/剩餘入口相對標頭的偏移 |
| 入口−4 | 每個入口前一個字 = 它自己的偏移:由跳板得到入口後,`入口 − [入口−4]` 就是標頭,再核對 +3C.. |
| 程式 | 入口位移由這次建置決定(`ui_strings_code.h`),**改程式碼不再升版本**,不同建置的層互認(`test_layer_compat.py`) |

**名字從哪來、怎麼認（使用者 2026-10-06 定）**：Loader v3 跑 entry 期間把服務表放在 `SL_SVC_AT`（`0xC072F6FC`），
uishare 自己去拿，呼叫它的 sup 不用傳任何東西：名字 = `svc->self()` 的主檔名；
認層 = 標頭版本對，且名字等於 `svc->holder(點, i)` 列出的某個持有者的主檔名（登記簿說了算，不是記憶體）。
表有效的條件：非 0、版本 ≥ 3、`done_at_start == [LOAD_DONE_US]`（過去開機留下的指標不算）。
**沒有 Loader v3 在跑**（AutoRun/stage2 卡，或舊的 v2 LOADER）：名字一律 `"FSDL"`，只認這個名字。

**⚠ 堆疊對齊(2026-10-06 修正,兩輪)**:
- v1、v2 與 v3 最初版的 `ENTER` 是 `sub sp,#4; push {r3,r4}`(12 bytes):整個層執行期間 sp 比入口錯 4;
  中斷用 STRD 把上下文存進這個堆疊時可能 data abort(記憶 arm-stack-alignment)。
- **韌體本身不保證在這些點以 8 對齊的 sp 呼叫**:靜態掃直接呼叫者,`C05E5B58`(解析)有 4 個、`C05E6400` 有 1 個、
  `C05D90F0` 有 2 個呼叫者的框架是 4 (mod 8)(例如 `C05E7B40` push {r4,r5,lr} 後直接 bl);raw-view 另找到
  `C0568950`/`C056D028`/`C05818B8`/`C05689A8`。所以只維持「相對入口」對齊不夠。
- 現在:`ENTER` 依入口奇偶用 16 或 20 bytes 的框架(`tst sp,#4`),從 push 起 sp **絕對** 8 對齊;框架存呼叫者的 sp,
  `LEAVE` 用它還原,尾呼叫依框架大小 `ldr pc,[sp],#8/#12`;r1/r3/r4/ip/lr/sp 原樣、尾呼叫不加深的契約不變(r2 當暫存,
  韌體函式本來就會改 r2)。原廠規則的分支改成先算完再 LEAVE。入口位移 56/288/452。
- QS 三層的 ARM 入口先 `bic` 對齊再進 C,返回前還原;uishare 的 C 加 `-mstackrealign`(clang 給葉函式的框架只對齊 4,
  例如 `uis_layer_code` push 9 個、不減 sp;-mstackrealign 只保證相對對齊,絕對對齊靠入口)。
- 守衛 `test_stack_alignment.py`:入口 sp ≡ 0 與 ≡ 4 各跑一次,每條指令檢查;舊 ENTER、第一輪修正(固定 16 bytes)、
  拿掉入口對齊、拿掉 -mstackrealign 都會失敗。
- **相機卡上 2026-10-06 之前建的 10LOSS、30OG3K(以及任何 v1/v2 字串層的 sup)都有這個問題**,用這版重建即修正。

v1（+00 `"FSDL"`、+04 版本 1）、v2、v3 **互不承認**：一張卡上所有用字串層的 sup 必須用同一版 uishare 建，
否則後裝的那個認不出前一層 → UIS_HOOK → 它的字串不裝。

下一個 sup 只在安裝時讀標頭；韌體從頭到尾不讀。

## 5. 對 sup 的要求

- 私有字串**不再進池**。FPUI 區塊裡 `stock_at = NOT_STOCK` 的字串、以及提示對不上的字串，
  全部放進這個 sup 的一層；**不掃池**（舊的「找不到才掃 176 KB」整段拿掉）。
- 要在自己程式裡用私有位移（例如 OG 的記錄 hook 產生的字串位移）：在 FPUI 區塊宣告，
  開機時由套用器把發到的位移寫進自己的資料（`STRBASE`），**不寫死 `FFFFFFF2` 這類值**。
  拿到位移前（層還沒裝上）不要讓韌體看到私有位移：照原廠記錄走。
- 比字串用位移，不用絕對位址（uishare 守則 4 照舊）。

## 6. 頁面（下一步，尚未定案）

字串點是「查詢」：每層只回答，不改輸入，所以能套娃。頁面不同：

- **只改字、不插入**（OG 的 List max +1 與摘要、raw-view 的計數）：目前整頁複製。候選：
  記錄解析器 `C05E6400` 逐筆替換（OG 的 360 筆 QS 已經這樣做）。
  難處：一層替換記錄後交給內層，內層看到的是替換後的暫存複本，用來源位址認不出來 →
  需要約定「原始記錄位置」怎麼往內傳，且不能改韌體參數。未解前不動頁面。
- **要插入列**（Lossless、screenflip）：暫時保留複本，但複本要留空間、後來的 sup 在原區塊插入，
  不要每個 sup 再複製一次。

## 7. 證明（每次改層的程式都要）

- 單層、兩層、三層、任意順序：每個原廠位移的解析結果與原廠函式逐值相同；私有位移各回各的字串。
- 擁有／剩餘：原廠池內外的指標與原廠相同；私有字串指標 → 擁有、剩餘到自己的 data_hi。
- 掛鉤點上是不認得的 B.W → 不裝、不改任何字。
- 原廠 free / realloc 在模擬器裡碰到私有指標：不呼叫真的 free、memcpy 不越界。
- 每項至少一個 mutation（把範圍比較 off-by-one、漏掛一點、不認標頭直接接上）證明測試會失敗。
